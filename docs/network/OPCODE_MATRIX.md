## KDDI-only reference commands

Commands such as chat `0x67xx`, GSLOGIN `0x1031`, and GSINFO `0x6916` describe
the Java KDDI reference server. They are excluded from the PAL implementation
matrix until a PAL client send/receive path or capture proves a mapping. The
reference’s TCP 8590 relay is an architecture hypothesis, not a PAL endpoint
(`docs/spec/kddi-reference-spec.md:447-453,590,676`).

## The `0x6502`/`0x6504`/`0x6510` rows describe one structure, not three

T17 (`SESSION-LOG-2026-08-02.md`, 2026-08-02) proved from main-EE disassembly that these commands are
four views of a single client-side structure, which is why their rows above share so many unknowns:

- An array of entries at `0x365e20`, stride `0x260`, count in `uRam00365e1e`, current index in
  `uRam00365e0c`. The stride is computed identically in `FUN_001c7a70` (`0x001c7b38..0x001c7b48`) and
  `FUN_001c8790` (`0x001c8930..0x001c8940`).
- Each entry holds a `0x3e`-bounded field at `+0x000`, a `u16` record count at `+0x158`, a `u32` at
  `+0x15c`, and 64 record pointers at `+0x160`. The layout closes exactly on the `0x260` stride.
- Records come from one pool (base pointer `iRam00365e14`, stride `0x134` per `0x001c7fdc li v1,308`)
  whose 64 slots are owned through the table at `0x3619d0`.
- `0x6502` mode 1 writes the entry's `+0x15c`; `0x6504` fills the records; `0x6510` writes one BE16
  into each record at `+0x12c` and rewrites the entry's `+0x000` field.
- `0x6510` reaches those records through the SAME pointer array `0x6504` wrote
  (`0x001c808c` writes, `0x001c88fc` reads), so this is pointer identity, not parallel arithmetic.

Correlation direction matters for any server implementation: `FUN_001c85c0` identifies records BY KEY
(each record's `unknownField0`), and `FUN_001c8790` consumes the reply BY POSITION (word `i` at cursor
`+ i`). A server may match on the key but must answer in request order.

The `0x40` limit is a CLIENT residency budget across resident entries, not a server-side limit on how
many records may exist. Records per entry are separately capped at 64 by the pointer array width.
