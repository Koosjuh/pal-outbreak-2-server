## R-022 - the field codec word is server-supplied connection state (2026-08-02, T18)

Grade: main-EE decompile plus ELF command/dispatch tables read directly from the executable,
corroborated by four captures.
Claims: `FUN_001c3b90` and `FUN_001c3f40` both pass `*(u16 *)(connection + 0x4c)` into the field
transform with header byte 5 of the frame being parsed or built; the only writer of that connection
field in the transport corpus is `FUN_001c4100`, which stores a BE16 taken from a received payload;
the ELF tables bind that handler to entry `0x03`, command `0x1002`, DIRECTION `0x01`.

CORRECTION, made before commit after independent review: the captured server sends `0x1002` with
direction `0x02` (`0000021002000000`, frozen in `server-v2/test/tcp10127-service.test.js`), and the
tables map command `0x1002` direction `0x02` to entry `0x04`, flag `0x08`, handler `0`. `FUN_001c4100`
therefore never ran in any captured session, `+0x4c` was never written from the wire, and the codec
word on those connections was simply its initialized value. Do not describe the captured pre-browser
exchange as having supplied it.

Independently corroborated value: all four captured `0x1007` identity fields decode and checksum with
codec byte `0` and with no other tested value, so that initialized value behaves as zero.

Actionable corollary: a server that wants to SET the client's codec word must send `0x1002` with
direction byte `0x01`, not the `0x02` the current pre-browser transcript sends. Untested.
Consequence: the server knows this word, and because the client verifies the server's own fields with
it, a server that encodes with a different value makes `FUN_001c3b90` return -3. A verifying checksum is evidence about the plaintext, not proof that the codec state was chosen
correctly, so V2 decodes only under the word the connection is known to hold and fails closed.
Corroboration: the existing `0x6510` request fixture's record field decodes at sequence `0xd8` with
codec byte `0` to `SLOT0001`, the `unknownField0` sent in the preceding `0x6504` - the key round-trips.
