## Behavioral explanation
The decompiler cannot recover this function: the 20-byte region decodes to
`halt_baddata()` ("Bad instruction — Truncating control flow"). It is reached from two
teardown/reset paths (FUN_005ac400 and teardown_overlay_state FUN_00606e40), where it is the
**first** call in the sequence. That call position is consistent with a subsystem-stop veneer
(e.g. an indirect jump into a linked library routine that stops audio/DMA before the overlay
state block is wiped), but the bytes as decoded are not valid MIPS from this entry — most
likely a misaligned decode of a jump/branch delay-slot or an overlay relocation the static
disassembler did not resolve.
