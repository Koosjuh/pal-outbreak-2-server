## Behavioral explanation
Allocates and opens a sceDbcMan **socket/endpoint**. It builds an open-descriptor on the stack (from a
caller-supplied 16-byte address `param_1`, or all-zero if `param_1 == NULL`), forces the descriptor's
mode fields (`hdr[0] |= 1`, `hdr[1] = 1`), and calls `dbcman_open` (fn 0x301) passing the endpoint
type `param_2` and `param_2 + 0x80` as the two extra parameters. On success `dbcman_open` returns the
socket-table **index**; this function records the type into the slot (`+0x18`), marks the slot in-use
(`+0x08 = 1`), and activates it via `FUN_0017eb20`. The `param_2` low bits must be clear
(`(param_2 & 0x3f) == 0`) — an alignment/class constraint — else it errors out.

## Input / output
- `param_1` (`long`) — pointer to a 16-byte address/id (or 0 for a null/wildcard address).
- `param_2` (`ulong`) — endpoint type/class; **must be a multiple of 0x40** (`& 0x3f == 0`).
- Returns `long`: socket-table index (`>= 0`) on success; `-1` on bad `param_2`.

## Side effects
- Fills stack descriptor, calls `dbcman_open` (RPC fn 0x301).
- On success: `sock_table[idx].type = param_2` (`idx*0x334 + 0x277c18`); `sock_table[idx].in_use = 1`
  (`+0x277c08`); `FUN_0017eb20(idx)` (register/activate).

## Important branches
- `(param_2 & 0x3f) != 0` -> `FUN_00114ac8(0x258970)` (log bad arg), return -1.
- `param_1 == 0` -> zero descriptor (`hdr[2..4]=0`, addr low byte cleared, `hdr[0]=0`).
- `param_1 != 0` -> copy 4 words header + 16-byte addr from `param_1`.
- `dbcman_open >= 0` (valid index) -> record type/in-use, activate. (`< 0` -> returned as-is, slot
  untouched.)

- Descriptor `hdr[0] |= 1`, `hdr[1] = 1` — open-mode flags handed to the IOP.
- `param_2 + 0x80` — the second open parameter (an offset/window applied to the type).
- Socket table base `0x277c00`, stride `0x334`; `+0x08` in-use, `+0x18` type.
