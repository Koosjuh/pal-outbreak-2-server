## Behavioral explanation
Constructs a **two-part tagged record** in the caller's buffer (`param_1`). It writes a fixed **8-byte magic** (`0x2588d0`) as the record header, appends a 5-byte formatted field (`0x2588e0`), then at sub-offset `+0x10` writes a 2-byte sub-tag (`0x2588e8`), fills the sub-record from `param_3` (`fill_subrecord`), and appends a trailing field (`0x2588f0`). The 8-byte magic at `0x2588d0` is the **same signature scanned for by `find_tagged_record` (0x0017c920)** — this pair builds and later locates records of one type. The exact record purpose (a session/connection descriptor, a serialized request) is unresolved without the tag bytes.

## Input / output
- `param_1` : `void*` destination record buffer (main part at +0x00, sub-record at +0x10).
- `param_2` : unused in body (present in signature; likely a length/context passed through by ABI).
- `param_3` : source for the sub-record fill (`fill_subrecord`).
- **return** : void.

## Side effects / control flow (linear, no branches)
1. `blob_copy_n(param_1, 0x2588d0, 8)` — write 8-byte magic header.
2. `field_format(stack, 0x2588e0, 5)` then `field_append(param_1, stack)` — append 5-byte formatted field.
3. `blob_copy_n(param_1+0x10, 0x2588e8, 2)` — sub-record 2-byte tag.
4. `fill_subrecord(param_1+0x10, param_3)` — populate sub-record from param_3.
5. `field_append(param_1+0x10, 0x2588f0)` — append trailing field.

// Build a 2-part tagged record: 8-byte magic + field, then a sub-record at +0x10.
// The 8-byte magic 0x2588d0 is what find_tagged_record() (0x0017c920) matches on.
void build_tagged_record(void *rec, /*ctx*/ void *unused, void *src)
{
    blob_copy_n(rec, TAG_MAGIC8 /*0x2588d0*/, 8);       // FUN_0010a4f0

    u8 tmp[16];
    field_format(tmp, TAG_FIELD5 /*0x2588e0*/, 5);      // FUN_00109728

    fill_subrecord(sub, src);                           // FUN_0017c748

}
