## Behavioral explanation
Asynchronous sceDbcMan **bulk send on data channel 2, function 0x8000131b** (dedicated client-data
`0x27afb0`, separate IOP RPC server bound at init). Copies up to `0x1080` payload bytes into the
channel-2 buffer `0x27b28c` and fires an **async** RPC (`mode 1`) so the EE does not block on the DMA.
Before firing it checks the channel isn't already busy (`sif_rpc_bind_ready` == 1 means a prior async
call is still outstanding → "SendData2 BUSY"). Semaphore-guarded around the buffer fill.

## Input / output
- `param_1`, `param_2` (`undefined4`) — header words -> buffer `+0x00`, `+0x04` (dest/id).
- `param_3` (`int *`) — payload length (bytes); must be `< 0x1081`.
- `param_4` (`u8 *`) — payload source.
- Returns `undefined4`: `1` = queued for send; `0` = oversize, channel busy, or RPC error.

## Side effects
- `WaitSema(uRam0027e540)`; `iRam0027b288=*param_3`; `uRam0027b280=param_1`, `uRam0027b284=param_2`;
  copies `*param_3` bytes `param_4` -> `0x27b28c`.
- `sif_rpc_call(0x27afb0, 0x8000131b, mode=1 (async), 0x27b280/0x1090, …)`.
- `SignalSema(uRam0027e540)` on every exit after the WaitSema.

## Important branches
- `*param_3 >= 0x1081` (oversize) -> log `0x258b80` with the length, return 0 (no sema taken).
- `sif_rpc_bind_ready(0x27afb0) == 1` (channel still busy) -> log "SendData2 BUSY", SignalSema,
  return 0.
- RPC dispatched (`>= 0`) -> SignalSema, return 1.
- RPC dispatch `< 0` -> log "sceDbcSendData2 rpc error", SignalSema, return 0.

## Constants & flags
- `0x8000131b` = dbcman fn SEND_DATA2 (async).
- Channel-2 max payload = `0x1080`; buffer total `0x1090` (header 0x0c + payload).
- Async mode arg = `1` to `sif_rpc_call` (bit0 ASYNC).
- `sif_rpc_bind_ready` reused here as the "previous async completed?" predicate (busy = 1 → wait).
