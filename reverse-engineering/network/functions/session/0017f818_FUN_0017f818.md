## Behavioral explanation
Synchronous sceDbcMan **request/response transaction, function 0x80001319**, guarded by the shared RPC
semaphore (`uRam0027e540`). Same wire shape as `dbcman_ctl_recv` (0x31a) — two arg words + an in/out
length + payload in scratch `0x27b00c` — but this variant **sends** the caller's payload up (copies
`param_4` into the scratch before the call) and, on success, reads the returned length back. The
semaphore makes it safe to call from multiple threads sharing the `0x27b000` scratch.

## Input / output
- `param_1`, `param_2` (`undefined4`) — request words -> `+0x00`, `+0x04`.
- `param_3` (`int *`) — in/out length; in = payload bytes to send, out = bytes returned (on success).
- `param_4` (`u8 *`) — payload buffer to send up.
- Returns `int` = `iRam0027b20c` (IOP status, `>=0` ok / `<0` error); `0` on RPC transport failure.

## Side effects
- `WaitSema(uRam0027e540)` … `SignalSema(uRam0027e540)` around the whole transaction.
- `iRam0027b008 = *param_3`; copies `*param_3` bytes `param_4` -> `0x27b00c`.
- `sif_rpc_call(0x27af88, 0x80001319, sync, …)`.
- On success (`iRam0027b20c >= 0`): `*param_3 = iRam0027b008`.

## Important branches
- `sif_rpc_call < 0` -> log `0x258b60`, SignalSema, return 0.
- else: if `iRam0027b20c >= 0` write back `*param_3 = iRam0027b008`; SignalSema; return `iRam0027b20c`.

## Constants & flags
- `0x80001319` = dbcman fn TRANSACT (send+recv, semaphore-guarded).
- Semaphore `uRam0027e540` serialises the shared `0x27b000` control scratch.

int dbcman_transact(u32 a0, u32 a1, int *iolen, u8 *payload)   // param_1..4

    g_dbc_rpc.len = *iolen;                  // iRam0027b008
    g_dbc_rpc.w0  = a0;                       // uRam0027b000
    g_dbc_rpc.w1  = a1;                       // uRam0027b004

                          g_dbc_rpc.buf, 0x280, g_dbc_rpc.buf, 0x280, 0);

}
