## Behavioral explanation
Polls a socket slot for a ready event/result — the "is this endpoint ready / pull its status" call.
It first ensures the slot is **bound**: if the bound flag (`+0x0c`) is clear it attempts a lazy
`dbcsock_bind`, and gives up (return 0) if that fails. It then asks whether the endpoint has a pending
locally-cached result (`FUN_0017ecc0`):
- **No cached result** (`== 0`): it queries the IOP via `dbcman_ctl_recv` (fn 0x31a) into a 16-byte
  stack buffer and returns the first status byte.
- **Cached result present** (`!= 0`): it reads the endpoint status record (`FUN_0017ec58`); if that
  record's `+0x04` field is non-zero (result valid), it returns the record's status byte; otherwise it
  re-binds and, on success, still returns the status byte.

On any failure of the bind/recv path it clears the bound flag (`+0x0c = 0`), calls `FUN_0017eb20`
(deactivate/reset), and returns 0.

## Important branches
- `bound == 0` **and** `dbcsock_bind(idx) < 0` -> return 0 (couldn't bind).
- `FUN_0017ecc0(idx) == 0` (no cached result): `dbcman_ctl_recv(idx, 0x101800c, len=4-in-selector,
