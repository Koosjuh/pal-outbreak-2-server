## Behavioral explanation
Readiness predicate for the SIF-RPC client-data managed by `sif_rpc_bind`/`sif_rpc_call`
(0x00115a98 / 0x00115c68). Given the client-data block `param_1`, it returns 1 iff the bind has
completed: the node pointer is non-null, the cached server-id in the client (`param_1[1]`) still
matches the node's current server-id (`node+0x18`), and the node's status word (`node+0x10`) has bit0
set. Otherwise 0. This is the `sceSifCheckStatRpc`-style poll used after an async
`sif_rpc_bind`/`sif_rpc_call` to know when the transaction is complete before touching the result
buffer.

## Input / output
- `param_1` (`int *`) — SIF client-data block (same layout the bind/call stubs populate).
  - `[0]` = node ptr; `[1]` = cached server-id.
- Returns `undefined4`: `1` = bound/ready, `0` = not yet / invalid.

## Side effects
- None (pure read).

## Important branches
- `node == 0` -> return 0 (never bound).
- `param_1[1] != *(node+0x18)` -> return 0 (server-id changed / node reused: stale).
- `(*(node+0x10) & 1) == 0` -> return 0 (busy: completion bit clear).
- All three hold -> return 1.

## Constants & flags
- `node+0x10` **bit0 = DONE/READY** status flag (set by the SIF reply path).
- `node+0x18` = current server-id, compared against the client's cached copy for staleness.

## Corrected reconstruction

enum { SIF_STAT_DONE = 1 };             // node+0x10 bit0

int sif_rpc_bind_ready(sif_client_t *cd)   // param_1
{
    sif_node_t *node = cd->node;        // *param_1
    if (node != NULL
        && cd->srv_id == node->server_id      // param_1[1] == *(node+0x18)
        && (node->status & SIF_STAT_DONE))    // *(node+0x10) & 1
        return 1;
    return 0;
}
