## Behavioral explanation
A `setsockopt`-style setter over a per-endpoint control table (base `iRam0037e944`, count
`iRam0037e940`, stride `0x38`). It sets a **boolean mode** (`param_2`, 0 or 1) on endpoint `param_1`.
The odd guard `if (param_2 == entry[+0xc]) entry[+0xc] = param_2;` is a no-op when the mode is
unchanged; when the mode **changes**, it takes the else branch and **resets the endpoint's running
state** — counters/pointers at `+0x14`, `+0x2c`, `+0x30`, a shared word `uRam0037e950`, and a 16-bit
field at `+0x20` — before storing the new mode. This is the classic "toggling this option invalidates
the accumulated stream/window state" pattern. Bounds- and range-checked.

## Input / output
- `param_1` (`int`) — endpoint index; must be `< iRam0037e940`.
- `param_2` (`uint`) — new mode; must be `<= 1`.
- Returns `undefined4`: `0` on success; `0xfffffff5` (-11) index out of range; `0xfffffff4` (-12)
  mode out of range.

## Side effects
- On mode change: `entry[+0x14]=0`, `entry[+0x2c]=0`, `entry[+0x30]=0`, `uRam0037e950=0`,
  `*(u16*)entry[+0x20]=0`, then `entry[+0x0c]=param_2`.
- On no change: writes `entry[+0x0c]` back to itself (no-op).

## Important branches
- `param_1 >= iRam0037e940` -> return `0xfffffff5` (index OOB).
- `param_2 > 1` -> return `0xfffffff4` (bad mode).
- `param_2 == entry[+0x0c]` -> no-op write, return 0.
- `param_2 != entry[+0x0c]` -> reset state block, store new mode, return 0.
