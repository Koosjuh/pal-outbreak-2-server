## Behavioral explanation
Same net-RPC family as 0x00100838, but a **bind/attach-only** operation for **service 0x80000595** (client node `0x208650`). It stashes `param_1` as the command word, ensures the RPC thread, and — if the service is not yet bound (`DAT_002074bc < 0`) — spins `sif_rpc_bind` until the server-ready word is non-zero, latches the bound-flag, and returns success. No `sif_rpc_call` is issued: this is the lazy **channel-open / readiness gate** for service 0x595 (called before the request wrappers that reuse it).

## Input / output
- `param_1` : `u32` command/context word (stored to `DAT_0020749c`).
- **return** : `1` if the service is bound & ready (already-bound fast path or after successful bind); `0` on failure (mutex not owned, or thread-ensure failed).

## Side effects
- WaitSema/SignalSema on `DAT_002074a8`; `DAT_0020749c = param_1`.
- On first use latches `DAT_002074bc = 0` after the bind+ready spin.
- Trace on `ram0x00207490 > 0`.

## Important branches
- `PollSema != handle` → not owner → if debug, trace `0x24e998` and return 0; else return 0.
- `rpc_thread_ensure(1) != 0` → SignalSema, return 0.
- `DAT_002074bc >= 0` (already bound) → **fast return 1** (does not re-bind, does not SignalSema — the fast path returns while still holding the mutex per decompile).
- else bind loop: retry `sif_rpc_bind(0x208650, 0x80000595)` on negative; break when `DAT_00208674 != 0`; latch flag; return 1.
