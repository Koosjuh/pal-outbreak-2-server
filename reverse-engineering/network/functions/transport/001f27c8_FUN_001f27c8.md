## Behavioral explanation
**Synchronization / poll** for the async device RPCs (fno 1/2/5). Two modes selected by `param_1`:
- **mode 0 (blocking wait):** `WaitSema(DAT_0024e430)` — blocks until the completion handler signals
  the semaphore — then reads the result via FUN_001f2878 into `*param_2`, and returns 0. (Note: this
  path does **not** re-signal the sema; the SignalSema in the raw is on the success return — see below.)
- **mode 1 (non-blocking):** `sceSifCheckStatRpc(client 0x37e9e0)` (FUN_00115e60); if the RPC is idle
  (returns 0) read the result and return 0; if still in progress return 1 (busy).
- other `param_1` -> return -0xb (invalid mode).

`iopdev_rpc_init` calls it with mode 0 right after `iopdev_rpc_enumerate` to block for the device count.

## Input / output
- `param_1` — poll mode: `0` = block, `1` = check-and-return.
- `param_2` — out pointer; receives the completion result word from FUN_001f2878.
- **Returns** `s64`: `0` = completed (result written), `1` = still busy (mode 1 only), `-0xb`
  (0xfffffffffffffff5) = invalid mode, `-1` = uninitialized.

## Side effects
- mode 0: WaitSema then SignalSema(DAT_0024e430) (per the raw success path); `*param_2 = FUN_001f2878()`.
- mode 1: no sema op; `*param_2 = FUN_001f2878()` only when idle.

## Important branches
- `DAT_0024e430 == -1` -> return -1.
- `param_1 == 0` -> WaitSema; `*param_2 = read_result()`; SignalSema; return 0.
- `param_1 == 1` -> `if (sceSifCheckStatRpc(client) == 0) { *param_2 = read_result(); return 0; } else return 1;`
- otherwise -> return -0xb.

- `FUN_001f2878` reads the delivered RPC result (word). `FUN_00115e60` = SIF RPC in-progress check.
