## Behavioral explanation
Pointer-array twin of `FUN_00189bb0`. Identical per-descriptor init, but the descriptors are **not
contiguous** — `param_1` is an array of *pointers* (`u32 *`), and element `i` is `*(param_1[i])`
(each `piVar3 = puVar5 + i`, then `*piVar3` is the descriptor base). Same `0x190`-byte descriptor
layout, same `0xffff` sentinels, same zeroed state words, same `+0x40` sub-object construction, same
`FUN_0018a400(desc, hdr, i)` bind pass.

The finalise pair differs slightly: it calls `FUN_00189f00(param_1, *puVar5, 0)` (note: passes the
pointer table *and* the first descriptor `puVar5[0]`) then `FUN_0018a0b0(*puVar5)` (finalise the first
descriptor). So this variant links via the pointer table and finalises starting from element 0.

## Input / output
- **Param 1** (`param_1`): base of a pointer table; `param_1[i]` → descriptor `i`.
- **Param 2** (`param_2`): selector/handle for `thunk_FUN_00197ad0(param_2,param_2,0)`.
- **Return:** `undefined4` — constant `1` (success). No failure path.

## Side effects
- For each of `n = hdr->count16` descriptors (`*param_1[i]`): stamps `+0xc2 = n`, sets
  `+0x180=+0x182=0xffff`, zeroes `+0xcc/+0xd0/+0xd4/+0xd8/+0x178/+0x17c`, constructs `+0x40` sub-object.
- `FUN_0018a400` binds each to record row `i`.
- `FUN_00189f00(table, table[0], 0)` + `FUN_0018a0b0(table[0])` finalise.

## Important branches
- Loop bound `n = hdr->count16`; `n<=0` skips both loops. No NULL-guard on `hdr` or on the pointer
  entries — caller must guarantee a populated table and a valid record.
