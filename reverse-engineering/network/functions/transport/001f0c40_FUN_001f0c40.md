## Behavioral explanation
Thin synchronous SN@P-IPC stub: uploads a fixed 0x200-byte (512) blob to the IOP-resident SN@P
module as library call **fno 0x3a**. It is one of a large family of stubs that all wrap
`snap_ipc_call_rpc` (0x1ef400): take the shared IPC mutex, marshal arguments into the shared TX
buffer at 0x37cf00 (payload at +0x1c), issue the blocking `sceSifCallRpc` (via FUN_00115c68) on
queue 0x37df10, then read the u16 reply status from RX+0x18 (0x37bf18) and release the mutex.

The 0x3a call is a **set-large-data** operation: the caller-supplied 0x200-byte buffer is copied to
tx+0x1c and a zero terminator is written at tx+0x21b (the byte just past the blob). Send size 0x220
= 0x1c header region + 0x200 payload rounded up to 16 bytes; the reply carries only a status word.

## Input / output
- `param_1` — pointer to a 0x200-byte source blob (copied verbatim into the request).
- **Returns** `u16` reply status read from RX+0x18 (0 = OK on the successful-status convention used by
  the sibling stubs; negative/non-zero = IOP-side error). [inferred sign convention]

## Side effects
- Writes 0x200 bytes to the shared TX buffer (0x37cf1c), one 0 byte at 0x37d11b.
- Sets `uRam0037d11b = 0`.
- Performs a blocking SIF RPC round-trip to the IOP SN@P module (mutates IOP-side session state per
  fno 0x3a; exact field set is external to this binary).
- Overwrites the shared RX buffer 0x37bf00 with the reply.
- Acquires/releases the SN@P IPC mutex (ef3e0/ef3f0) — serialises with every other snap_req_* stub.

## Important branches
- None. Straight-line: lock → copy → RPC → read status → unlock → return. No bounds/error gate in
  the EE stub; validation happens IOP-side and is surfaced only as the returned status word.

## Constants & flags
- `0x3a` — SN@P IOP library selector for this call.
- `0x220` — TX size (16-byte aligned by snap_ipc_call_rpc). `0x20` — RX size.
- `0x200` — payload length. `0x21b` — offset (tx+0x1c+0x1ff) of the trailing NUL.
