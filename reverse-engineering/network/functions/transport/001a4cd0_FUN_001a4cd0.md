## Behavioral explanation
Synchronous wrapper around the 2-arg operation `FUN_001a5550`. It brackets the call so that the
caller returns only after the operation and all the events it generated have been fully drained:
1. Arm/acquire the completion flag `FUN_0019ec60(0x8000000c, 1)`.
2. Run `FUN_001a5550(param_1, param_2)`; keep its result `lVar1`.
3. Only if `lVar1 >= 0` (success): open the drain (`FUN_001a2430`), then **pump** — while
   `FUN_0019eb00(1) > 0` (events pending) yield via `FUN_00111668(0)`; then while
   `FUN_0019ec60(0x8000000c, 1) > 0` (flag still signalled) yield again; finally close the drain
   (`FUN_001a2490`).
4. Return `lVar1` (the operation's result, unchanged by the drain).

This is the blocking form of an otherwise-async RPC: issue, then spin-yield until the transport
reports quiescent. `FUN_001a56f0` is the same wrapper for a 3-arg operation.
