## Behavioral explanation
Bulk-initialises a **contiguous array of fixed-size descriptors** (stride `0x190` = 400 bytes) from a
source header record. The element count `n` is read from the header (`hdr->count16` at `+2`). For each
of the `n` descriptors it: stamps the count into the descriptor (`+0xc2`), sets two `0xffff` sentinel
fields (`+0x180`, `+0x182` — "unassigned/invalid" markers), zeroes six state words
(`+0xcc,+0xd0,+0xd4,+0xd8,+0x178,+0x17c`), and initialises an embedded sub-object at `+0x40`
(`FUN_00186320`). A second pass binds each descriptor to its record row via `FUN_0018a400(elem, hdr,
i)`. Finally two whole-array passes run: `FUN_00189cf0(base, base, 0)` and `FUN_0018a0b0(base)`
(link/activate/finalise).

The `0x190` stride, `0xffff` sentinels and two-phase (zero → bind) layout are the signature of an
array-of-slot descriptors being (re)initialised at subsystem start. `FUN_00189db0` is the
pointer-array twin of this function.

## Side effects
- Writes `n * 0x190` bytes of the array (fields below).
- Calls `FUN_00186320` on each `elem+0x40` sub-object (constructs it).
- `FUN_0018a400` binds each descriptor to record row `i`.
- `FUN_00189cf0` + `FUN_0018a0b0` finalise the whole array.

## Important branches
- Loop bound `sVar1 = hdr->count16`. If `n <= 0` both loops are skipped and only the two finalise
  passes run over an empty array (still returns 1). No NULL-check on `hdr` — a NULL header would
  fault at `*(short*)(hdr+2)`; the caller is expected to guarantee a valid record.
