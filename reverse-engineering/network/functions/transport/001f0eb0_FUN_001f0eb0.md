## Behavioral explanation
Synchronous SN@P-IPC setter, library call **fno 0x4f**, carrying a single u32 argument written at the
**start** of the TX buffer (tx+0x00, `uRam0037cf00`) — unlike the 0x1c-offset used by most stubs.
Blocking round-trip (send 0x20 / recv 0x20); returns the u16 reply status. Pairs naturally with the
fno 0x4d getter (which reads from RX+0x00): both operate on a request/reply slot at buffer offset 0,
suggesting a distinct "control/state" attribute group from the +0x1c keyed calls.
