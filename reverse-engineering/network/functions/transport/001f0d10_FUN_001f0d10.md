## Behavioral explanation
Synchronous SN@P-IPC **query**: sends one 16-bit argument (fno 0x3c) and returns both a status word
and an out-parameter result word. Writes the arg to tx+0x1c, performs the blocking round-trip (send
0x28 / recv 0x28), copies the reply data word from RX+0x20 into `*param_2`, and returns the RX+0x18
status. This is the "look up an attribute keyed by a small id" shape of the family.

## Input / output
- `param_1` — `u16` key/index sent to the IOP module (tx+0x1c).
- `param_2` — out pointer; receives the u32 result word from RX+0x20.
- **Returns** `u16` status from RX+0x18.

## Side effects
- `uRam0037cf1c = param_1`; `*param_2 = uRam0037bf20` (reply data).
- Blocking SIF RPC to the IOP SN@P module (fno 0x3c); overwrites shared RX buffer.
- Acquires/releases the SN@P IPC mutex.

## Important branches
- None; lock → store key → RPC → copy result → read status → unlock.

## Constants & flags
- `0x3c` — SN@P IOP library selector. `0x28` — TX and RX sizes (payload word at +0x1c, result at +0x20).
