## Behavioral explanation
SN@P transport RPC stub for opcode **0x2b = room ENTER** (named in the protocol brief: "transport room
ops … 0x2b enter"). Parameterless from the EE side — the room to enter has already been selected by the
preceding prepare (0x26) / list flow on the IOP side, so ENTER just commits the join. Its wrapper
`FUN_001ef040` sets in-room mode flag `0x37a2a6 := 1` after a successful call; opcode 0x2c
(`snap_room_exit`, FUN_001f0840) is the counterpart that clears it. This ENTER is the transport-level
room join that gates in-room state (roster/chat/scenario) server-side.

## Input / output
- **Inputs:** none (target room is IOP-side session state).
- **Returns** (u16): IOP status word from `B+0x18` (success/failure of the enter).

## Side effects
- `WaitSema`/`SignalSema` on `0x37aee0`; overwrites shared buffers A/B; blocks on the RPC.
- On return the caller sets `0x37a2a6 := 1` (now-in-room).

## Important branches
None in the stub. Success/failure is encoded in the returned status; the caller does not branch on it
(it unconditionally sets the flag), so the flag reflects "enter attempted", not a checked success.

## Constants & flags
- Transport fno `0x2b`. `ssize=0x20`, `rsize=0x20`. Status at `+0x18`.
- In-room flag: `0x37a2a6` (op2b → 1 enter, op2c → 0 exit).

## Corrected reconstruction

```c
// SN@P transport RPC stub — opcode 0x2b: ROOM ENTER (commit join to the prepared room).
// Wrapper FUN_001ef040 sets g_in_room (0x37a2a6) = 1 afterward. Pair: op2c exit.
u16 snap_room_enter(void)
{
    snap_ipc_lock();                                       // WaitSema(0x37aee0)
    snap_ipc_call_rpc(0x2b, SEND_A, 0x20, RECV_B, 0x20);   // header-only ENTER

    snap_ipc_unlock();                                     // SignalSema(0x37aee0)
    return status;
}
```
