## Behavioral explanation
SN@P transport RPC stub for opcode **0x38** — the **create** request, the largest send in the batch
(`ssize=0x128`). It stages a **name string** into the send buffer at `A+0x1c` (via `FUN_00109eb8`, the
blob/string copy) — or zeroes that field when `param_1 == 0` (nameless/default) — followed by two u32
parameters at `A+0x11c` and `A+0x120`. It returns a **short handle/index** in `B+0x18`. Its wrapper
`FUN_001ee720` normalises the result (`!= -1 ? result : -1`) and sets the created/owner mode flag
`0x37a2a4 := 1`; opcode 0x39 (`snap_room_close`, FUN_001f0bf0) is the counterpart that clears it. This
is the transport-level **room/slot create** primitive — directly relevant to the create-room roster work
(the IOP-side registration that a created room needs before the host is inserted as player-1).

## Input / output
- **param_1** (const char*): room/slot name. `0` → name field zeroed; else copied to `A+0x1c` (buffer
  reserves `0x11c-0x1c = 0x100` bytes for it).
- **param_2** (u32): first create parameter, staged at `A+0x11c` (`uRam0037d01c`).
- **param_3** (u32): second create parameter, staged at `A+0x120` (`uRam0037d020`).
- **Returns** (u16/short): created handle/index in `B+0x18`; `-1` (0xffff) signals failure (wrapper
  clamps it).

## Side effects
- `WaitSema`/`SignalSema` on `0x37aee0`; overwrites shared buffers A/B; blocks on the RPC.
- Caller sets created/owner flag `0x37a2a4 := 1`.

## Important branches
- `if (param_1 == 0) A+0x1c = 0;` (clear name) `else FUN_00109eb8(A+0x1c, param_1);` (copy name).
- Failure path is in the wrapper, not the stub: `result == -1` → keep `-1`; else return `result`.

## Constants & flags
- Transport fno `0x38`. `ssize=0x128`, `rsize=0x20`. Name at `+0x1c` (up to `0x100`B), params at

- Created/owner flag: `0x37a2a4` (op38 → 1 create, op39 → 0 close).
- Sentinel: `-1` (0xffff) = create failed.
