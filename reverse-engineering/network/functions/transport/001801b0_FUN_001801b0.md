## Behavioral explanation
Allocates a transaction slot from the global request table `iRam0027e5a8` (up to `0x280` = 640 slots
of `0x180` bytes each), serialises the caller's request descriptor `param_1` into a freshly allocated
message buffer, tags it with the current sequence id, and submits it via `FUN_00180340`. Returns a
1-based slot handle (`idx+1`) on success, or 0 if submission failed (slot is then released).

The message buffer layout is: a fixed `0x24`-byte header (copied from the descriptor) followed by two
16-byte-aligned variable-length payload blobs — payload A of length `desc[7]` from `desc[2]`, then
payload B of length `desc[6]` from `desc[4]`. `param_2` is a type/flags word stored in slot word 0;
its **bit2 suppresses the buffer build** (a control/no-payload request).

## Input / output
- `param_1` — request descriptor (`uint*`, `puVar7`):
  - `[0]` -> slot`[1]`; `[3]` -> slot`[2]`;
  - `[2]` = payload-A ptr, `[7]` = payload-A len;
  - `[4]` = payload-B ptr, `[6]` = payload-B len;
  - first `0x24` bytes = the header copied verbatim into the message buffer.
- `param_2` (`uint`) — request type/flags -> slot`[0]`. **bit2 (0x4) = NO_BUFFER** (skip serialise).
- Returns `int`: `idx+1` slot handle on success, `0` on submit failure.

## Side effects
- Consumes a slot in `iRam0027e5a8` (memset to 0, then populated); slot`[4]`=buffer size,
  slot`[5]`=buffer handle, slot`[3]`=sequence id (`uRam0028a3f0`), slot`[0x14]`=slot`[0x15]`=0.
- Allocates a message buffer (FUN_00184170, alignment class 3) when a payload is built.
- Enqueues the slot (FUN_00180340); on failure releases it (FUN_001829c0).

## Important branches
- Slot scan: first entry with `+4 == 0` is free; scan caps at index `0x280` (no explicit
  overflow guard beyond the cap — see uncertainty).
- `(param_2 & 4) == 0` (build buffer): size = `0x30 + align16(desc[7]) + align16(desc[6])`; alloc;
  copy `0x24` header; copy payload A at `buf+0x30`; copy payload B after A (16-byte aligned).
- `(param_2 & 4) != 0`: skip buffer build entirely (control message).
- `FUN_00180340(...) == 0` (submit failed): `FUN_001829c0(idx+1)` release, return 0.
- else return `idx+1`.

## Constants & flags
- `0x280` (640) — request-table capacity; `0x180` — per-slot stride.
- `0x4` (`param_2 & 4`) — NO_BUFFER / control-request flag.
- `0x30` — message-buffer header/prefix size (payload A starts here); `0x24` — descriptor header
  copied in.
- `align16(x) = (x + 0xf) & ~0xf` — payload blobs are 16-byte aligned.
- Alloc class `3` (FUN_00184170 second arg).

#define REQ_SLOTS     0x280
#define REQ_STRIDE    0x180
#define REQ_NO_BUFFER 0x4          // param_2 bit2
#define ALIGN16(x)   (((x) + 0xf) & ~0xfu)

extern u8   g_req_table[REQ_SLOTS][REQ_STRIDE];  // iRam0027e5a8
extern u32  g_req_seq;                            // uRam0028a3f0

int request_slot_alloc_and_submit(const req_desc_t *desc, u32 type)  // param_1, param_2
{
    // find first free slot (slot->w4 == 0)
    u32 idx = 0;
    while (idx < REQ_SLOTS && ((req_slot_t*)&g_req_table[idx])->w4 != 0)
        idx++;

    req_slot_t *slot = (req_slot_t *)&g_req_table[idx];
    memset(slot, 0, REQ_STRIDE);                 // FUN_001840a0

    slot->w1   = desc->w0;                        // slot[1] = desc[0]
    slot->w2   = desc->w3;                        // slot[2] = desc[3]
    slot->type = type;                            // slot[0] = param_2
    slot->w14  = 0;                               // slot[0x14]
    slot->w15  = 0;                               // slot[0x15]

    if (!(type & REQ_NO_BUFFER)) {
        u32 sz = 0x30 + ALIGN16(desc->lenA)       // desc[7]
                      + ALIGN16(desc->lenB);      // desc[6]
        slot->buf_size = sz;                      // slot[4]
        slot->buf_hnd  = aligned_alloc_cls(sz, 3);// slot[5], FUN_00184170
        u8 *buf = handle_to_ptr(slot->buf_hnd);   // thunk_FUN_00197ad0
        memcpy(buf,        desc,        0x24);     // header
        memcpy(buf + 0x30, desc->ptrA, desc->lenA);            // payload A  (desc[2],desc[7])
        memcpy(buf + 0x30 + ALIGN16(desc->lenA),
               desc->ptrB, desc->lenB);                        // payload B  (desc[4],desc[6])
    }

    slot->seq = g_req_seq;                         // slot[3] = uRam0028a3f0

    if (submit_request(slot, desc) == 0) {         // FUN_00180340
        release_slot(idx + 1);                      // FUN_001829c0
        return 0;
    }
    return idx + 1;                                 // 1-based handle
}

## Remaining uncertainty
- No explicit full-table guard: if all 640 slots are busy the scan lands at index `0x280` and writes
  one stride past the array (a latent overflow) — unless a caller-side gate prevents saturation.
  Not runtime-checked.
- `req_desc_t`/`req_slot_t` field names inferred from offsets; the semantic of payload A vs B (e.g.
  header-args vs body) not decoded. Whether this table is the SN@P app request queue or a lower DNAS
  queue is unconfirmed.
