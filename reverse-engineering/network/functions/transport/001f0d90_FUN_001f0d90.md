## Behavioral explanation
Synchronous SN@P-IPC **no-argument getter**: library call **fno 0x4d** with an empty request; returns
a status word plus one result word taken from the *start* of the RX buffer (RX+0x00, not the usual
+0x20). Used to read a global SN@P state value (e.g. a current-state / count / id) that needs no key.

## Input / output
- `param_1` — out pointer; receives the u32 at RX+0x00 (`uRam0037bf00`).
- **Returns** `u16` status from RX+0x18.

## Side effects
- `*param_1 = uRam0037bf00`.
- Blocking SIF RPC to the IOP SN@P module (fno 0x4d); overwrites shared RX buffer.
- Acquires/releases the SN@P IPC mutex.
- No TX payload is marshalled (send buffer content is whatever it last held; size 0x20).

## Important branches
- None; lock → RPC → copy result → read status → unlock.

## Constants & flags
- `0x4d` — SN@P IOP library selector. `0x20` — TX/RX sizes. Result offset RX+0x00 (distinct from the
  +0x20 used by keyed queries such as 0x3c).
